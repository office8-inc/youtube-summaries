## 💡 概要

この動画は、企業向けに Claude Code 上で AI オペレーティングシステム（AI OS）を構築してきた発信者が、そのやり方から離れつつある理由を語ったものです。  
過去4ヶ月で4社に泊まり込みの「AIメイクオーバー」を実施し、ケープタウンで7人、バリで7人、モンテネグロのイベントでは約35人の創業者のセットアップを支援した現場感からの結論だとしています。  
問題は3点で、セットアップに丸一日かかること、引き渡し後に創業者が使いこなせるか不安なこと、そしてエージェントやアプリを自分で作らせるには技術的な学習曲線が高すぎることです。  
代わりに使い始めたのが Kylon というプラットフォームで、Slack のようなルームとエージェント構築、Lovable 的なアプリビルダーが1つにまとまっており、CLI から一括セットアップできる点を最大の利点に挙げています。

## ⭐ 重要なポイント

- 過去4ヶ月でオンサイトの「AIメイクオーバー」を4社、グループセッションを3回（ケープタウン7人、バリ7人、モンテネグロ約35人）実施した経験からの判断だと述べている。  
- Claude Code ベースのAI OSの問題は3つ。①APIキー集めやChatGPTエクスポート、質問票で**セットアップに丸一日**かかる ②スキルやコンテキスト管理を創業者に理解させる訓練が必要 ③エージェント・アプリを自分で作るにはVPSやホスティングなど技術的な学習曲線が高い。  
- 発信者のサービスは継続支援型ではなく「7ヶ月分のAIの進歩を7日で」引き渡す形なので、顧客の自走可能性が最優先になる。逆に長く伴走するエージェンシー型なら、学習コストの高さはむしろ機能になりうるとも指摘。  
- 代替として紹介するのが Kylon。コミュニケーション用の「ルーム」に人間とエージェントを同居させ、その上に Lovable 的なビルダーでアプリを組める。会社URLからディープリサーチでコンテキストを収集し、YouTube や Gmail の接続は数クリックで済む（Google Cloud経由なら30分かかる作業）。  
- 開発者視点での決め手は **CLI があること**。ワークスペースの構造・エージェント・権限・スキルをUIを触らずプログラム的に流し込め、引き渡し後も外から変更できる。直近のメイクオーバーでは40人規模の会計部門をこの構成で立ち上げたという。  
- 2023年のカスタム知識チャットボットが GPTs の登場で一掃されたのと同じ構図が繰り返されている、というのが全体の見立て。
